# NRGOPT Energy Intelligence 使用指南

## 每天先看哪里

登录后先打开“六国全景”。六张国家卡始终同时展示；没有可靠来源的国家会显示“尚未采集”，不会用示例数据填满页面。

页面中的“任务与预算状态”说明自动扫描是否启用、调用预算是否可用，以及最近通知是否已接受、待发、失败或结果不明。显示“预算暂停”时，系统没有继续发起付费调用；这不代表市场没有新变化。

三个雷达负责发现和分类情报：

- 触发雷达回答“为什么现在值得关注”；
- 需求雷达回答“谁需要解决什么供能问题”；
- 项目雷达回答“项目到了哪一步”。

一条情报可以进入多个雷达。机会、采购、合同和交付属于后续商业阶段，不是另外几个雷达，也不要求每条情报逐级升级。

## 怎样看一条情报

先看四个彼此独立的字段：重要性、证据状态、商业成熟度和行动紧迫度。重要不等于已经核实，项目成熟也不等于适合参与。

点击候选标题进入来源详情页，重点查看：

1. 中文变化摘要和“为什么值得关注”；
2. 已知事实及对应的英文原文引文；
3. 未知事项、假设、反证和下一观察信号；
4. 原始来源链接以及是否有独立来源支持。

“来源已绑定”表示引文确实存在于保存的原文；“部分事实已交叉核对”表示列出的部分事实得到另一独立来源支持；“来源冲突”表示同一项目、字段、时间和范围出现了不能同时成立的说法。

## 人工需要做什么

阅读情报不需要逐条审批。AI 负责发现官方来源、保存原文、提取事实、校验引文并进行基础交叉核对。

“中文注释”只用于记录自己的业务判断，例如客户关系、参与条件或下一步动作。没有额外判断时可以留空。

## 怎样补充来源

在“来源工作台”可以让当前配置的来源发现服务查找指定国家的一手来源，也可以粘贴公开网页地址。系统会重新抓取原始网页，搜索摘要不会直接成为证据。保存后再由当前配置的情报分析服务根据已保存原文生成中文情报。

服务商、API 地址、模型、币种、每月金额上限和 API Key 在“服务配置”页面管理。“来源发现”和“情报分析”分别计算当月用量，达到各自上限后会在下一次付费调用前停止。API Key 已由服务器配置时可以留空保存；重新填写表示替换。页面和接口不会读回完整密钥。

遇到以下情况应保留未知，不自行补猜：正文无法取得、项目范围不清、容量口径不同、采购截止日期未披露，或多个来源存在真实冲突。

## 自动扫描、通知与归档

自动扫描以六国任务逐项运行。重复触发同一计划不会重复建立任务；失败、待重试和预算暂停会保留在全景页。没有有效预算时，手动来源搜索和情报分析同样会在调用前停止。

飞书通知分为重大变化、每日摘要和系统告警。真实群机器人未配置时，系统只保留待发能力，不会发送。发送超时会标为“结果不明”，不会无限自动重发。

“服务配置”中的“通知静默时间”默认启用北京时间 23:00—07:00。可更改时区、起止小时，或关闭静默。静默期间消息留在队列，不消耗发送尝试；结束后由后续通知任务发送。重大提醒默认也遵守静默，只有勾选“允许重大提醒突破静默”后才例外；日报和系统告警仍延后。保存该设置不会启用尚未配置的飞书发送，已经在发送中的消息也不会被撤回。

已保存原件先进入 Supabase 私有暂存，再由 Mac 拉取脚本下载、核对大小和 SHA-256，并写入本地 manifest。归档完成不会自动删除云端原件；只有一个本地副本时仍不满足删除条件。

## 配置历史与调用记录

“服务配置”页下方保留最近 30 个配置版本和 30 次调用。修改模型、服务地址、币种、计费方式、上限或密钥会生成新版本；普通预算同步不生成版本。历史记录不保存密钥内容。

调用关联启动时使用的配置版本；切换模型不会改写已经开始的调用。成功、失败、尚无完成回执分别显示，服务商返回的 token 用量单独保留，不换算为消费金额。启用追踪前的旧调用和旧分析没有版本记录，不事后猜测。若显示尚无完成回执，应先核查，不要反复手动触发同一笔调用。

日报会列出本次纳入的来源证据摘要，分别展示事实、NRGOPT 判断、未知事项和下一观察点。每份最多列出五条，超出部分保留到后续摘要；迟到证据不会因为错过上一份日报而被丢弃。已发送重大提醒的事项在日报里只保留一行详情链接。采集失败或暂停时明确显示覆盖不完整。

通知去重使用原件哈希和同一网址的引文集合。同一原文重新分析不会因为中文措辞或评级变化再次通知；这个规则不等于已经实现所有跨网址、跨项目的语义去重。重大提醒还要求来源发布日期明确且在最近 30 天内；历史、未来日期和未知日期的材料保留在站内和日报。迁移前的旧资料建立静默基线，不集中补发旧消息。

来源详情中的“项目与包件持续记录”保留本来源内的项目和独立包件 ID 与状态历史。施工、EPC、设备、服务等包件分开记录；本次分析没有再次提到的旧包件标记“未再次确认”，不代表取消。记录日期是系统保存时间；同一原文同时披露多个阶段时不擅自选定当前阶段。不同来源的同名对象尚不自动合并，这也不是完整的商业机会管理功能。
